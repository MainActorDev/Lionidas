# Wait Step Implementation Plan

- Source: `brainstorm/20261015T220500Z-wait-step-yaml.md` — user approved "both" (condition + time forms in v1; 10s default timeout)
- Status: READY
- Decisions locked: both forms v1 · default condition-timeout 10s · bare number = ms · wait is a STEP (never a modifier) · pure-time waits legal everywhere; condition waits require a running app

## Objective

Case YAML gains a `wait:` step with two semantics:
1. **Condition form** — poll-and-probe until an observable holds, then proceed immediately; fail honestly on timeout.
2. **Time form** — literal sleep, self-documenting via optional `for:`.

Measurable completion:
- `wait: 500ms`, `wait: 1s`, `wait: 1500` parse, execute, and round-trip through case-yaml (save/load/versions)
- `wait: {until: <label|identifier|screen.state>, timeout: 8s}` polls ~250ms, passes the moment the condition holds, fails with "waited Ns for X" on timeout
- Evidence rows record form, target, timeout, actual elapsed, outcome
- Validation: condition-wait before any launch setup in a fresh case is refused (no app to probe); durations parse (ms/s/bare-ms) with clear errors
- Foodiary-shaped live check: cold-launch case with `wait: {until: <welcome text>}` proceeds when the splash dismisses

## Scope

IN: shared YAML grammar (parse + serialize + validate), engine executor + probe reuse, evidence logging, step-label rendering, authoring surfaces (yaml completions if present), tests, live drill.
OUT: changing `expect` semantics; global auto-settle; per-app timeout settings (later if needed); lint rules (docs only this pass).

## Grammar (shared/src/case-yaml.ts)

```
- wait: 500ms            # time
- wait: 1s               # time
- wait: 1500             # time (bare = ms)          — BOUND: max 60s (review R3)
- wait: { for: splash, time: 7s }                  # time + reason
- wait: { until: home_login_bar_login_button }     # condition: bare string → identifier first, then label (same resolution order as on:)
- wait: { until: "Get Started" }                   # condition: bare string (text or identifier)
- wait: { until: text: "Get Started" }             # condition: explicit label text
- wait: { until: screen: splash.dismissed }        # condition: registry screen.state (DOTTED form — never doubly nested)
```

**until-value shape rule (review R1)**: `until:` is EITHER a bare string OR a map with EXACTLY ONE key — `text:` or `screen:` (dotted `a.b`). The doubly-nested `until: {screen: {…}}` spelling is INVALID. BARE = identifier-then-label at runtime, matching the `on:` precedent.
**Bounds (review R3)**: time form ≤ 60s; condition `timeout:` ≤ 120s (default 10s). Beyond → INVALID quoting the limit.

Parsed shape (one action `wait`):
```ts
action: 'wait';
wait: { mode: 'time'; ms: number; for?: string }
     | { mode: 'until'; target: { kind: 'identifier' | 'text' | 'screen'; value: string; state?: string }; timeoutMs: number };
```

Serializer emits the compact user syntax (not the JSON-ish intermediate). Duration parser: `/^(\d+)(ms|s)?$/` — no suffix = ms; anything else = INVALID with the offending token quoted.

## Engine (server/src/manual/)

- Executor branch `case 'wait'` in the playback step dispatch.
- Time mode: `await sleep(ms)` — literal; log `$ wait 500ms (for: splash) → slept 503ms actual`.
- Until mode: loop { probe(); if held → break; if now > deadline → FAIL `waited ${timeout} for ${targetLabel}: never saw it` } with 250ms cadence. Probe implementations REUSE the existing resolution paths: identifier/label → the same AX/view-tree query `expect` uses for existence; screen.state → the same registry-state probe `expectScreen` uses. No new probe machinery.
- Evidence (review R4 — no schema change this pass): details ride the EXISTING step result text plus a compact JSON log line: `wait {"mode":"until","target":"splash.dismissed","timeoutMs":10000,"elapsedMs":5231,"outcome":"met"}` (mode time uses for/ms).
- Abort: waits must honor run-abort between polls (check the run's abort signal each loop iteration; time-mode sleeps chunked into ≤250ms slices for the same reason).

## Validation (case validate)

- Duration grammar errors quoted verbatim.
- `until:` requires a resolvable target kind: bare string → OK (identifier-or-label at runtime), `text:` OK, `screen:` must match `<screen>.<state>` shape (registry existence NOT required at validate time — same rule as expectScreen today, which allows drafting before registry activation).
- A condition-wait as the FIRST step of the OUTER case with NO setup block emits a WARNING (not a refusal — review R2: runFlow children may legitimately open with a wait because the parent launched; setup-present implies launch): `wait-until before any launch — nothing to probe yet (first step, no setup)`. runFlow children and setup blocks never warn.
- Step-label: `wait 500ms` / `wait until home_login_bar_login_button (≤10s)` / `wait until splash.dismissed (≤10s)`.

## Stages

1. **Grammar + round-trip** (shared/case-yaml): parse/serialize/duration grammar + tests incl. malformed (`wait: 7x`, negative, missing unit value).
2. **Engine executor + evidence**: time + until modes, probe reuse, abort-awareness, honest failure text + tests (fake probe source: appears after N polls; never-appears timeout path asserts the failure string and elapsed).
3. **Validation + labels + docs**: validate rules, stepLabel rendering, vocabulary docs table row.
4. **Live drill**: Foodiary cold-launch case — setup `wait: {until: text: "Get Started", timeout: 12s}`; assert proceed-after-splash (actual elapsed ≈ splash duration, not timeout) + evidence row correctness.

## Edge cases

- `wait: 0ms` — legal no-op (documented; useful as a settle breath).
- Two consecutive waits — legal (user's explicit choice; the engine doesn't optimize steps).
- `until` target that ALREADY holds — passes on first probe (0 polls beyond the first).
- Timeout smaller than poll cadence — single probe then fail; fine.
- Condition wait inside runFlow child cases — same rules; child inherits run abort.
- Round-trip fidelity: `for:` and `timeout:` survive save/load without reordering fields.
